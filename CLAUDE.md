# FindMeVinyl

A personal Android app (Kotlin, Jetpack Compose) for finding record shops, browsing artist discographies and keeping a want list. It is a hobby project in a public repository, so nothing personal or work-related belongs in this file or in commits.

## How to work on it

- Work test first. For each new behaviour: write the failing test, run it and check it fails for the right reason, write the least code that passes, then run the whole suite.
- Keep steps small. Say briefly what changed and why.
- Run `.\gradlew testDebugUnitTest` after every change (PowerShell on Windows). Roughly 230 tests pass today, and all of them must still pass before moving on.
- Run one class with `.\gradlew testDebugUnitTest --tests "com.nickallport.findmevinyl.shops.OpeningHoursTest"`.
- Test reports are in `app/build/reports/tests/testDebugUnitTest/index.html`.
- Ask before adding a dependency or changing a version. Several versions below were chosen to fix real problems.
- Never stage `local.properties`.
- Keep `README.md` up to date in the same pull request as the change that makes it out of date. Check it whenever a change adds, removes or alters a feature, a setting, a screen, a web service the app calls (the table of data sources, and the privacy section if what is sent changes), how to build or test, or what contributors are asked to do. Say what was checked, or changed, under Changes in the pull request. The README is a public page for people who have not read this file, so write what the app does, not how the code does it, and keep to the plain style used there. Do not put counts that change with every pull request in it (such as the number of tests). When a screen changes a lot, retake its picture in `docs/screenshots` on the emulator with the default settings and no personal data (cover art and artist photos from the app's own sources are fine).

## Layout

The package root is `com.nickallport.findmevinyl`.

- `musicbrainz`, `nominatim`, `overpass`: Retrofit interfaces, DTOs and mappers for the three public APIs.
- `artist`, `discography`, `favourites`, `wantlist`, `shops`, `export`: logic and view models for each feature.
- `storage`: the Room database, entities and DAOs.
- `location`: the device location lookup.
- `coverart`: the Cover Art Archive URL and `CoverArtLoader`, which downloads album covers.
- `image`: `ImageLoader`, which downloads any image by URL. `CoverArtLoader` is a thin wrapper around it. `wikidata`: the Wikidata API, used to find artist pictures.
- `ui.*`: composables only (`ui.artist`, `ui.discography`, `ui.favourites`, `ui.shops`, `ui.wantlist`, `ui.theme`).

Conventions:

- View models are plain classes, not `androidx.lifecycle.ViewModel`. They sit beside the logic they serve, not under `ui`, and expose suspend functions that return a UI state.
- Screens are stateless composables. A "Route" composable owns the state and takes suspend functions as parameters, so tests can pass fakes and never touch the network.
- `MainActivity` wires everything together. Navigation is a sealed class `Screen` plus a `BackHandler`.
- Composable tests run on the JVM with Robolectric. Network tests use MockWebServer. Pure logic tests use plain JUnit.

## Stack and versions

Kotlin 2.2.10, Android Gradle Plugin 9 with built-in Kotlin, KSP 2.2.10-2.0.2, Room 2.7.2, Retrofit 2.11.0 with Gson, OkHttp 4.12.0 (declared explicitly), Robolectric 4.13, MockWebServer 4.12.0.

- Gradle has to run on JDK 21. On JDK 25 Robolectric fails with "Unsupported class file major version 69". Check with `.\gradlew --version`.
- `gradle.properties` contains `android.disallowKotlinSourceSets=false`. KSP needs it with AGP 9. Keep it.
- Do not set `ksp.useKSP2=false`. It breaks the build with AGP 9.
- Do not downgrade Room below 2.7.2. Room 2.6.1 generates broken code for suspend DAO methods under KSP2.
- `app/src/test/resources/robolectric.properties` sets `sdk=34` because the app targets SDK 37 and Robolectric stops at 34. Keep it.

## Rules learned the hard way

- DAO methods are `suspend`. Room refuses main-thread queries in the real app, and tests use `allowMainThreadQueries()`. DAO methods return `Long` or `Int` instead of `Unit`.
- When syncing albums from MusicBrainz, use `insertIfNotExists` or `insertAllIfNotExist` (IGNORE) and never `insert` (REPLACE), so a user's owned and wanted flags are not overwritten. Save a whole discography with `insertAllIfNotExist`, which is one transaction. 419 single inserts took 7 seconds on the emulator.
- MusicBrainz returns 25 results unless asked for more, and at most 100 a page. `DiscographyViewModel.discography(artistId)` is a `Flow` that asks for 100 at a time and follows the pages to the `release-group-count`. Each request starts at least 1.1 seconds after the previous one started, and it stops after 10 pages. Each page is saved as it arrives and a state is emitted after it, so the first page shows while the rest load. The list is always built from the saved albums (`loadSaved`), never from a response. An artist opened before starts with its saved albums, before any request. Once as many albums are saved as MusicBrainz lists, the remaining pages are skipped, so reopening an artist is one request. A first page that fails with nothing saved is an `Error`. Any other failure keeps the list and sets `loadError`, so the list is never silently short. Give `MockWebServer.takeRequest` a timeout in these tests.
- Taps on Owned, Want and Save must never reload the discography from MusicBrainz. `DiscographyRoute` calls `loadSaved` and copies the flags onto the albums on screen, album by album, so albums that arrived meanwhile are kept. Before this, every tap re-downloaded every page.
- MusicBrainz sends `"first-release-date": ""` for undated albums. The mapper turns it into null, and `loadSaved` also treats `""` as undated, because rows saved earlier have it. An empty string sorts before every real date.
- The emulator and this machine share one IP, and MusicBrainz limits requests per IP. Repeatedly reopening artists, format lookups and manual probes got "HTTP 503 ... busy" for several minutes. Keep emulator runs against MusicBrainz few, and wait when it answers 503.
- `DiscographyScreen` gives every row and header a key, so the list holds its place as pages add albums above what is on screen. Keep the keys.
- The format filter (`FormatFilter`, `FormatFilterBar`) works on what is stored. An album with `formats == null` has not been looked up, and it stays in the list while a format is chosen, marked "Checking formats…", until its lookup shows whether it matches. An album looked up with no known formats (an empty list) is checked and does not match. Chips and counts come from the albums known so far, so they grow as lookups arrive. The choice is `rememberSaveable` in `DiscographyRoute`, one format at a time.
- `DiscographyRoute` records every format lookup into its own state as it returns (`lookUpFormats`). Without that, the filter, the chips and the counts would be stale, because a row's own result stays inside the row. `refreshSaved` also merges formats from the saved albums, never replacing known formats with none.
- MusicBrainz answers carry `X-RateLimit-Limit` (400 was seen) and `X-RateLimit-Remaining`. Choosing a format while many albums are unchecked starts lookups for the rows on screen, one a second, for as long as it is on screen. Keep emulator sessions with a filter on short.
- `DiscographyViewModel.checkAllFormats` finds the formats of all of an artist's albums from `release?artist={id}&inc=release-groups+media&limit=100`, a hundred releases a request (Genesis is 12 pages, Bob Dylan 24), each page in its own `MusicBrainzThrottle` turn. The formats are saved at the end, in one go, because an album's releases can be on any page. A page answered 429 or 503 is asked for again after the throttle's pause, up to three tries, and any other failure ends the check as `Failed`. The result is `FormatCheckResult` (`Done`, `TooBig`, `Failed`). `DiscographyRoute` runs it once a visit when the discography has settled (not while pages are loading, and a load error does not stop it) and some album has no formats or old ones. Meanwhile the rows wait instead of looking up their own album, and what the check found is brought in with `refreshSaved`. It is a lot of requests for one screen: keep emulator runs against MusicBrainz few, because it makes the shared IP busy (HTTP 503).
- Anything that catches `Exception` around a suspend call must rethrow `CancellationException` first.
- Never hardcode the contact email in the User-Agent. `AppUserAgent.VALUE` is built from `BuildConfig.MUSICBRAINZ_CONTACT_EMAIL`, which comes from `musicbrainz.contact.email` in `local.properties`.
- Nominatim and Overpass are shared public servers. Always send the User-Agent, keep requests few, and keep the Overpass fallback and the `[timeout:25]` setting in the query. The shop search asks `overpass.openstreetmap.fr` first (15 second read timeout) and `overpass-api.de` second (30 seconds), because on 2026-10-16 overpass-api.de took 32 to 45 seconds or timed out in 3 of 4 searches, while the French server answered 12 of 12 in under 4 seconds (kumi.systems failed about half the time, and private.coffee always). `ShopSearchViewModel.queryWithRetry` asks the servers in turn and passes over one that fails, is too slow, or answers HTTP 200 with a `remark` starting "runtime error" (`OverpassResponse.failed`: a timed out query comes back as an empty, successful looking list, which must not be shown as "no shops"). If every server failed with a quick busy answer (429, 502, 503, 504) they are all asked again after a short pause, up to 3 rounds. A timeout or any other failure ends it after one round, because another would take as long again. The last failure is the one shown. The French server refuses a request with a generic User-Agent, so always send `AppUserAgent.VALUE`. Its usage policy could not be read on the server itself, so keep requests few. The query uses `nwr` so shops mapped as buildings are found.
- Nominatim returns latitude and longitude as strings.
- The `Surface` in `MainActivity` uses `Modifier.fillMaxSize().safeDrawingPadding()`. Keep it when editing that file. It sits inside a `Box` with the theme background, so the status and navigation bar areas follow the theme. Without the Box they were flat white and the clock was unreadable in dark mode.
- `OpeningHours` reads a subset of the OpenStreetMap hours syntax. Text it cannot read returns null and the shop row shows the raw text. Rules are read in order and a later rule overrides an earlier one on the days it matches, including public holidays (`PH`): `statusAt(moment, isPublicHoliday)` and `nextOpening(moment, isPublicHoliday)` take the holiday dates, and hours that do not name PH are the same on a holiday. `PH off`, `PH 10:00-14:00`, `Mo-Sa,PH 10:00-18:00` and an additional `Su,PH 15:00-19:30` all work. Without holiday dates, PH rules are ignored, and `OpeningHoursDescriber` adds "(public holidays may differ)". With them, that note goes, and a shop whose hours name PH says "(public holiday today)" on one.
- Public holidays: `PublicHolidayCalendar` gets them from Nager.Date (`date.nager.at/api/v3/PublicHolidays/{year}/{country}`, free, no key). Only a country code and a year are sent, and the user agent is plain `FindMeVinyl/1.0` with no contact address. The answer is kept in the `public_holidays` table (database version 6) for 90 days, per country and year, so it works offline after the first look and costs a request a country and year, not a search. Old rows are used when a new request fails. A 404 (no calendar for the country) is kept too, for 90 days. Only entries of type Public count, and an entry with `counties` only applies when the search's region (`ISO3166-2-lvl4` from Nominatim, such as GB-SCT) is one of them. `datesNear` asks for this year, and next year when the next week reaches into it. The region comes from Nominatim `addressdetails=1` on the town search, its other places and the reverse lookup of a nearby search, so it is the region of the search area, not of each shop. `ShopSearchRoute` loads the dates for the shown result's region and passes `isPublicHoliday` down to `ShopRow`.
- An owned album is never wanted. `toggleOwned` clears the wanted flag when it marks an album owned, `AlbumRow` hides `+ Want` on owned albums, and the `getWantedAlbums` query excludes owned albums so older rows with both flags do not show up.
- Look and feel: the app has its own palette in both light and dark (`ui.theme`), the teal and orange of the icon. Dynamic colour (the wallpaper) is off (`USE_DYNAMIC_COLOR`). `ThemeContrastTest` checks every text and background pair is at least 4.5:1, so change colours there first. The icon teal is too light for text or buttons on white (3.4:1), so light mode uses `TealDeep` for primary.
- Navigation has no menu. `Screen.Home` is the front screen (`HomeScreen`: the big logo and ARTISTS, WANTS and SHOPS buttons). Every other page gets a `Masthead` bar from `MainActivity`, and tapping it goes home. Back goes where `Screen.backTarget()` says: home from any page, from the results back to the Artists page, and from a discography back to where you came from. The Artists page (`Screen.Search`, `ArtistsScreen`) has a search field and the favourite artists. Searching opens `Screen.ArtistResults(query)` (`ArtistResultsRoute`), which searches when it opens unless `SearchResultCache` already holds results for that same query (`artistQuery`), so rotation and coming back from a discography never search again. Only a successful search is cached.
- The logo (`ui.brand.Logo`) is drawn in code with Android's built in `cursive` font, curved along an arc with `drawTextOnPath`. The three button icons (`Glyphs`) are path data, because the Material icons library is not a dependency. Ask before adding one.
- The Shops page (`ShopSearchRoute`) is a search field (the keyboard searches, like the Artists page) and a Near me button. It starts from the last result in `SearchResultCache.shop`, so coming back or rotating costs no request. The first time it opens with nothing kept it searches near you once by itself (`nearbyTried` stops it repeating, and is only set once the search has finished, so a rotation in the middle tries again). That is one Overpass request, which took about 20 seconds on the emulator. After that, only Near me or a typed town searches. A failed nearby search is kept and shown, and Near me tries again.
- Settings: the user chooses what to hide on a Settings page (`Screen.Settings`, `SettingsScreen`), reached from the quiet Settings button under the three big ones on the front screen. `Settings` is a data class of yes-or-no values, all of the form "hide X", with the user's own defaults (hide Digital, bootlegs, promos, unknown status releases and charity shops; the rest off). `SettingsStore` keeps them in the app's `settings` preferences file, one boolean each, and saves every one, even at its default, so a choice the user made survives a later change of default. A value of the wrong kind reads as the default. `AppSettings` holds the current `Settings` as a `StateFlow` and saves on `update` or `set`; `MainActivity` makes one and reads it with `collectAsState()`. A row of the page is a `toggleable` Row with the tag `setting_{name}`, and it passes on the whole `Settings` with that one changed. Albums the user owns or wants are never hidden by a setting, so they cannot lose track of them. Hiding charity shops (`hideCharityShops`, on by default) and second-hand shops (`hideSecondHandShops`, off by default, because some second-hand record shops are tagged `shop=second_hand` on OpenStreetMap) is done in `ShopSearchRoute` on what is shown: the kept result in `SearchResultCache` still has them, so switching a setting needs no new search, and a note under the place name says how many are hidden (`hidden_shops_note`) and goes to Settings. The note names the kind when only one kind was left out ("3 charity shops", "1 second-hand shop") and says "shops" when it was both (`hiddenNoun`). `HomeScreenTest` and `SettingsScreenTest` run in a taller test window, because the page does not fit the small default one.
- What the settings leave out of a discography is decided by `DiscographyVisibility.apply(grouped, settings)`, on what is shown, so changing a setting needs no new load. An album you own or want is never hidden. Otherwise it is hidden when its kind is hidden (live albums, compilations, singles, other releases; studio albums and EPs cannot be hidden), or when every format it is known to have come out on is hidden. LP, CD, 12", 7", MC (cassette) and Digital can be hidden (the label constants are in `ReleaseFormats`), 10" cannot. A hidden format is also taken out of the album's `formats`, so the row, the format chips and their counts do not show it (`displayFormats`, which keeps them all when that would leave none, for an owned album that is only on a hidden format). An album whose formats are not known yet, or are known to be none, is shown. `DiscographyRoute` takes `settings` (default `Settings.ShowEverything`, so tests are not about the settings), keeps the raw albums for taps and lookups, and builds the chips and the list from what is left. A note under the chips says how many albums were left out (`hidden_albums_note`) and goes to Settings. A lookup shows its formats through `displayFormats` too. `DiscographyRouteSettingsTest` runs in a tall test window.
- Hiding by release status (`hideBootlegs`, `hidePromos`, `hideUnknownStatus`) uses `albums.statuses` (database version 8, `MIGRATION_7_8`), the statuses of an album's releases as `ReleaseStatuses` tokens (`Official`, `Promotion`, `Bootleg`, `Other`, which covers Withdrawn, Cancelled, Pseudo-Release and no status), each once, sorted, joined with `|`. Null means never looked up, empty means none listed. Both the whole-artist check (`FormatCheckProgress.statusesByAlbum`, saved with the formats by `AlbumDao.setChecked`) and the per-album lookup (`loadFormats`) save them, so `setChecked` is the way to save a look at an album's releases. An album is hidden by status only when its statuses are known and non-empty, none is `Official`, and every one is of a hidden kind. Null or empty statuses leave it shown, as owned and wanted albums are. An album hidden by several rules is counted once in `hiddenCount`. `DiscographyRoute` starts the whole-artist check also when some album has `statuses == null`, so each artist saved before version 8 is checked once more (12 to 24 requests for the big ones), and calls `refreshSaved()` after a per-row lookup to bring the saved statuses onto the screen. Albums that none of the artist's releases belong to keep null statuses, so they ask for the check again on every visit, as they already did for formats.
- Tapping a shop opens its own page (`Screen.ShopDetail(shop, region)`, `ShopDetailRoute`, `ShopDetailScreen`) instead of going straight to a map. Back goes to the Shops page, whose kept result (`SearchResultCache.shop`) is still there, so it costs no request. `ScreenSaver` keeps the page by writing the whole `Shop` as JSON (Gson) and the region as two strings, so it survives a rotation and the process being killed. The page shows what OpenStreetMap has and leaves out what it has not: name and kind (with ", second-hand only" for `second_hand=only`, which a `shop=music` shop can have), whether it is open now, the address, phone, website and email, the hours of each day (`OpeningHours.hoursText`, with today in bold, and `publicHolidayText` as a "Public holidays" line), and an Open in map button (`openInMaps`, a `geo:` link). Hours that cannot be read are shown as written (`hours_raw`). The route looks up the public holidays of the shop's region like the list does. `Shop` carries `address` (`ShopAddress`: street, house number, postcode, city, country), `phone`, `website`, `email` and `secondHandOnly`, read by `OverpassShopMapper` from `addr:*`, `phone` or `contact:phone`, `website` or `contact:website`, and `email` or `contact:email`, blank values counting as missing. `ShopAddress.lines(fallbackCountry)` lays an address out the way the country does it: number before the street in GB, IE, US, CA, AU, NZ, ZA and FR, the postcode after the town in all of those but FR, otherwise street first and postcode first. The country is the one on the address, or the country of the search when the address has none (most do not), or neither, with the street first. The text comes from volunteers, so only what `WebLink.normalise` (http and https only, a bare host gets https), `PhoneLink.dialUri` (digits and a leading plus, at least five digits, first number only) and `EmailLink.mailUri` accept is ever handed to another app; anything else is shown as plain text. `MainActivity.openLink` starts the dialler, browser or mail app and shows a short message if there is none. OpenStreetMap has no photos of shops (none of 53 record shops in Lisbon, London and Dundee had `image` or `wikimedia_commons`).
- Favourite shops: a heart button on a shop's page (`shop_detail_favourite`, "Add to favourites" / "Favourite") keeps the shop, and tapping it again lets it go with no question. They are in the `favourite_shops` table (database version 9, `MIGRATION_8_9`, entity `FavouriteShopEntity`, `FavouriteShopDao`) with a snapshot of everything known about the shop when it was kept (name, kind, position, hours, address in parts, phone, website, email, second-hand only, and the region for public holidays), so the list and each shop's page work with no search and no network. `FavouriteShopsViewModel` adds (keeping again updates the snapshot), removes, reads the ids and lists the shops by town then name, ignoring case, shops with no town last. The id is the OpenStreetMap element as `node/123`, `way/123` or `relation/123` (`OverpassShopMapper`), because the numbers of the three kinds overlap. A Favourites button (`shops_favourites_button`) sits next to Near me on the Shops page and opens `Screen.FavouriteShops` (`FavouriteShopsRoute`, `FavouriteShopsScreen`): the shops under a heading for their town (`favourite_shops_town_{town}`, "Other places" when there is none), each a `ShopRow` that opens the shop's page. `Screen.ShopDetail` carries `backTo` (the Shops page, or the favourites), so Back goes where the user came from, and an older saved state with no `backTo` goes to the Shops page. A favourite in the search results has a small orange heart (`shop_favourite_heart`): `MainActivity` reads the ids each time the Shops page opens. Favourite shops are in a backup (`BackupFile.shops`, `BackupShop`) and restore only adds the ones not on the phone yet, skipping any with no id or a position outside the map; an unknown kind becomes a record shop.
- Adding a shop that OpenStreetMap does not have (`Screen.AddShop(sharedText)`, `AddShopRoute`, `AddShopScreen`), reached from the Add a shop button on the favourite shops page (`favourite_shops_add`) or by sharing from Google Maps into the app (an `ACTION_SEND` `text/plain` filter in the manifest, `launchMode="singleTask"` so a running app gets `onNewIntent`; `MainActivity.incomingShare` is turned into the screen by a `LaunchedEffect`; the app's own want list chooser excludes the app with `EXTRA_EXCLUDE_COMPONENTS`). What Google Maps gives has NO position in it: the Maps app shares the name, the address on the next line and a short link, and following the link (`MapsLinkResolver`: https only, only Google Maps hosts at every hop (`SharedPlaceParser.isMapsLink`), at most 5 hops read from the headers without loading the page, no cookies, redirects elsewhere end it) leads to `google.com/maps/place/Name,+Address/data=...`, again with no coordinates. A `share.google` link leads to a Google search page and is not followed. `SharedPlaceParser.parse` reads the shared text (name, address, link, or a pasted pair like `39.4036, -9.1349`), `fromPlaceUrl` reads a followed link (and a `consent.google.com` page's `continue` link). The position then comes from, in this order: coordinates pasted (exact), `ShopPositionFinder` (Nominatim, whole address first, then the town with the postcode taken off, a second apart, so at most two requests; the town is `approximate`), or the phone's position (`Use my position`, which asks for location permission). Nominatim usually knows the street, not the house (it matched Silver Tentacle's street to a few hundred metres), so the status says the position may be a little off. A shop added by hand has the id `custom/{uuid}` (`Shop.isCustom`), is saved at once as a favourite, `approximatePosition` and `mapQuery` (database version 10, `MIGRATION_9_10`) say when its position is only the town's and what text to search a map app for: `MapLinkBuilder.geoUri` then opens `geo:lat,lon?q=name, address`, so Google Maps finds the shop itself even when the position is rough. `ShopAddress.fromText` splits the one-line address into street, postcode and town so the shop sorts under its town. Shops added by hand are also listed in a search for the place they are near (`ShopSearchViewModel` `customShops`, within the search radius, once each). Opening hours cannot come from a Google Maps link (the share has only the name, the address and the link), so they are typed. `FriendlyHours.toOsm` turns plain wording into the form `OpeningHours` reads: "Mon-Sat 10-7; Sun closed" becomes "Mo-Sa 10:00-19:00; Su off". It accepts short and long day names, `to`, `&`, `weekdays`, `weekends`, `daily`, no days at all (every day), 24 hour times, am and pm, minutes with a dot, two spells in a day, and an end time smaller than the start with no am or pm taken as the afternoon (10-7 is 19:00). Text that is already in the OpenStreetMap form is kept as it is, and a rule that cannot be read makes the whole text unreadable (null). The form shows "Understood as: ..." under the field when the result differs from what was typed, a note when it is not understood (it is then kept as written and the shop does not say whether it is open), and nothing when it is already in the OpenStreetMap form. A shop added by hand has an Edit this shop button on its page (`shop_detail_edit`, only for `Shop.isCustom`), which opens the same page (`Screen.AddShop(null, editing = shop)`, `AddShopRoute(editing = ...)`, `AddShopForm.from(shop)`, `ShopAddress.toText`) with the details filled in, "Edit shop" as its title and "Save changes" on the button. Saving keeps the id, the email and anything else that is not on the form (`base.copy(...)`), and replaces the saved favourite. The position is kept unless the user pastes another or uses their own. A shop added from a Google Maps link keeps that link (`Shop.mapsLink`, database version 11, `MIGRATION_10_11`, `AddShopForm.mapsLink`, included in a backup): only a link that `SharedPlaceParser.isMapsLink` accepts is kept, and it is checked again when it is shown and when a backup is restored. The shop's page then has a View on Google Maps button (`shop_detail_google_maps`, `MainActivity.openLink` with `ACTION_VIEW`), which opens the place on Google's own page with the hours, photos and reviews that cannot be read into the app: the share has only the name, the address and the link, the Places service needs a billing account and a key, and reading Google's page is against its terms. Reading another link while editing replaces the kept one. Test names that open a database file must stay short (about 90 characters at most): a 107 character name made Robolectric's temporary folder too long for Windows and the test failed with "unable to open database file".
- List rows are cards: use `ui.common.ListCard` (rounded, tonal, tappable with `onClick`, `container` to make a row stand out) for shops, albums and the want list groups, and keep the existing test tags on them. The category headers on the discography screen have their own padding and the primary colour. `+ Want` is a pill, and Saved uses the quieter tonal button.
- Loading is shown with `ui.brand.RecordSpinner`, the logo's record turning once every 1.8 seconds (`drawRecord`, shared with the logo and the masthead, is `internal` for this), never with `CircularProgressIndicator`. It takes `modifier` (which carries the test tag, as the old indicators did: `loading_indicator`, `detail_loading`, `pressing_loading_{id}`) and `size` (56 dp, or 20 dp beside a line of text). Its box is the caller's modifier and the record sits in the middle of it, so `fillMaxWidth()` centres it. It says "Loading" to a screen reader and follows the system's animation settings. Rotation is seen only on a device: the sheen arcs move between two screenshots.
- There is no search button: `SearchField` searches on the keyboard's search key (trimmed, and not when blank). The logo bar is `focusProperties { canFocus = false }`, because focus moved onto it after the search key and left a grey band.
- Compose tests: `assertExists()` and similar are member functions, not imports. `weight()` needs no import inside a Row or Column. `onNodeWithText` fails when two nodes match, for example a text field and a result with the same text. A `LazyColumn` needs a bounded height, so give it `weight(1f)` inside a Column. A `clickable` row merges the nodes inside it, so finders for things inside it (the cover, for example) need `useUnmergedTree = true`.
- Rotation: small values (current screen, typed text) use `rememberSaveable`. Result lists never go in the saved-state Bundle, because a big city's shop list can exceed its size limit. Put them in `SearchResultCache` and save only a flag. `ScreenSaver` saves `Screen` as a list of strings.
- Album covers come from the Cover Art Archive at `coverartarchive.org/release-group/{id}/front-250`, using the MusicBrainz release group id the discography already has. A 404 means no art. `CoverArtLoader.shared` keeps images and 404s in memory, allows four downloads at once, sends `AppUserAgent.VALUE`, and returns null on any failure. `CoverImage` shows `ic_cover_placeholder` until a cover arrives and when there is none. The placeholder copies the art in `ic_launcher_foreground.xml`, so change both together.
- Release formats are fetched per album from `release?release-group={id}&inc=media&limit=100` and stored in `albums.formats` as MusicBrainz's raw names joined with `|` (a comma will not do, some names contain one), with `formatsCheckedAt`. Null means never fetched, an empty string means fetched and none known. `ReleaseFormats` turns the names into the labels (LP, 12", 10", 7", CD, MC, Digital), so the rules can change without fetching again. Formats are looked up only for rows on screen, and refreshed after 30 days. Every lookup goes through `MusicBrainzThrottle.shared`: one at a time, 1.1 seconds apart, a pause after a 429 or 503. A started lookup saves its result inside the throttle block, so cancelling the row does not lose it.
- Every change to a Room entity needs a version bump and a `Migration` in `storage/Migrations.kt`, never a destructive fallback, because it would delete a user's owned and wanted flags. Room writes each version's schema to `app/schemas`, and those files are committed. `MigrationTest` builds the old database from SQL, fills it with data, and opens it with the current database.
- Artist pictures on the search results come from Wikimedia Commons, found through an exact chain and never by name: MusicBrainz `artist/{id}?inc=url-rels` gives the Wikidata item, Wikidata `wbgetclaims` property P18 gives the file, and the address is `commons.wikimedia.org/wiki/Special:FilePath/{file}?width=120`. If Wikidata has no picture, MusicBrainz's own "image" link to a Commons file is used. `ArtistImageViewModel.loadImageUrl` keeps the result in the `artist_images` table (a null address means "checked, no picture", and is kept too), looks again after 90 days, and keeps nothing on a failure. Finding and saving run inside one `MusicBrainzThrottle` turn, so a cancelled row cannot lose a result. `ImageLoader.shared` downloads the picture. The search results show "Artist photos: Wikimedia Commons" while a picture is on screen, because Commons asks for credit. Do not match artists to pictures by name (Deezer put the wrong "Genesis" first).
- `SquareImage` is the one composable for the 56dp square with the record placeholder, used for album covers (`CoverImage`) and artist pictures (`ArtistImage`).
- `CoverArtLoaderTest` uses `@GraphicsMode(GraphicsMode.Mode.NATIVE)`. In the default mode Robolectric returns a fake bitmap for bytes that are not an image, where a device returns null. Give `MockWebServer.takeRequest` a timeout, because it waits forever when no request is made.
- Restore tests use `runComposeUiTest` with `StateRestorationTester(this)` and `emulateSaveAndRestore()`, under `@OptIn(ExperimentalTestApi::class)`. It takes a `ComposeUiTest`, not a rule.

- Tapping an album row opens `Screen.AlbumDetail` (`AlbumDetailRoute`, `AlbumDetailScreen`); Back goes to the discography it came from, and `ScreenSaver` keeps the whole chain. The row has an Owned pill (`owned_toggle`, "+ Owned" when not owned) and a `+ Want` pill. They no longer share the row's tap, so a test that toggles owned taps `owned_toggle`, not `album_row`.
- The detail page shows one pressing at a time, a rating, and a list of the album's pressings. `PressingChooser.candidates` gives the pressings: the official vinyl releases, earliest first; without vinyl the official releases of any format; without anything official every release. Undated releases come last. `ReleaseDates.sortKey` sorts a date known to the month or day before a bare year of the same year ("1970-10" before "1970", then "1971"), and is used for pressings, the discography and the want list's fallback order. The first candidate is the one the page opens on, and at most 30 are kept. `AlbumDetailsViewModel.load` makes three requests in one `MusicBrainzThrottle` turn, each in its own slot (`awaitNextSlot()`): the release list with `inc=media+labels` (the pressings), `release/{id}?inc=recordings+labels+release-groups+genres` for the first pressing's tracks, and `release-group/{id}?inc=ratings` for the rating. Details are stored in `album_details` (database version 4) as JSON (`AlbumDetailsJson`, which carries a `version`, now 3: a row with no version or another one reads as missing and is fetched again, so raise it when the stored layout or the order of the pressings changes), looked up again after 90 days. A failure of any request returns null and stores nothing. An album with no releases is stored as empty, so it is not asked about again for 90 days. Tapping another pressing calls `selectPressing`: one request (`inc=recordings+labels`), kept only in memory for the run of the app, shown with the album's own genres, pressings and rating (`AlbumDetails.withPressing`). The choice is not stored, so the page opens on the first pressing again. The `inc` lists are sent with `encoded = true`, because MusicBrainz reads an encoded plus sign as a literal plus.
- `TrackSections` groups tracks into "Side A/B" when track numbers are A1, B1 and so on, otherwise by disc. `CountryNames` turns MusicBrainz country codes into names (XW is Worldwide, XE is Europe). The large cover is `CoverArtLoader.loadLarge` (`front-500`), and `SquareImage` takes a `size`.

- The user orders things by hand, and only the Artists page and the Wants page show that order. `favourite_artists.position` orders the favourite artists, and `albums.wantPosition` orders a wanted album among its artist's wanted albums (database version 5). The want list and the share text are artists by `position`, then albums by `wantPosition`. Equal positions are ties: all rows start at 0 after the upgrade, and ties fall back to the old order (artists by name, albums by release date with undated last, then title). A move (`FavouritesViewModel` and `WantListViewModel` `moveUp`/`moveDown`, using `Reorder.swapped`) rewrites every position in that list as 0, 1, 2 and so on, so ties disappear on the first move. A new favourite (`saveFavourite`) goes first, one place before the lowest position (`ArtistDao.minPosition`, so positions can be negative until the next move rewrites them as 0, 1, 2), a newly wanted album (`AlbumDao.markWanted`) goes last, and saving a favourite that already exists must not change its position (`toggleWanted` saves the artist every time, and `toggleOwned` does when it marks an album owned, so both taps on a discography make the artist a favourite). The discography ignores `wantPosition` and stays in release order. `MoveButtons` is the shared up/down arrow pair, with its own tags: `favourite_up_{id}`, `favourite_down_{id}`, `want_up_{albumId}`, `want_down_{albumId}`.
- Sharing the want list asks first. The Share button on the Wants page opens a dialog (`share_dialog`) with an optional message (`share_intro`), a choice of how many albums (`share_limit_10`, `_20`, `_30`, `_50` and `share_limit_all`, only the ones smaller than the list, and none at all for a list of 10 or fewer) and a summary line (`share_summary`: "Sharing all 28 albums" or "Sharing the top 10 of 28 albums"), with Share (`share_confirm`) and Cancel (`share_cancel`). The choices are `rememberSaveable`, so they are kept over a rotation and for the next time the dialog opens in the same run of the app, but not after the app is closed. They go up as `ShareOptions(intro, limit)` and `WantListRoute` passes them to `exportText`. `WantListFormatter.format(items, intro, limit)` puts the trimmed message above the header with a blank line, and takes the first `limit` albums in the user's own order (artists by position, then albums by want position), which can stop in the middle of an artist. A limit that is not positive or is as big as the list shares everything, and a shorter one makes the header "My vinyl want list (top 10 of 28):".
- The favourite artists on the Artists page can be shown as a list (the default: picture, name and move buttons) or as a grid of pictures only, to fit many more on a screen. Two chips beside "Your favourites" switch between them (`favourites_view_list`, `favourites_view_grid`). `ArtistsScreen` holds the choice in `rememberSaveable`, starting from `startInGrid` and reporting each switch through `onGridChange`, and `MainActivity` keeps it in `FavouritesLayoutStore` (the `favourites_layout` preferences file, key `grid`), so it survives closing the app. It is a choice of look and is not in a backup. `FavouritesScreen(grid = true)` draws a `LazyVerticalGrid` with tiles at least 76 dp wide (four across on a 360 dp phone), each tile a square `ArtistImage(fillSize = true)` with the tag `favourite_artist_{id}` and the artist's name as its content description. A tile whose picture has not loaded, or has none, shows the name on a dark bar, since a record on its own does not say who it is. A quick touch opens the artist (the tile's `clickable`). Holding a tile for the long press time lifts it (bigger, on top) and shows its name, and dragging on moves it through the grid with the others making room (`animateItem`). The gesture is one `pointerInput` on the whole `LazyVerticalGrid` in `ArtistGrid`, not on the tiles, because a tile that has moved cannot follow a finger that began on it. It waits for the long press itself in the Initial pass (`awaitLongPressOrCancellation` was cancelled at once, because the tile's `clickable` takes the press), and once lifted it consumes the events in that pass so the grid does not scroll and the release is not a tap. Lifting the finger calls `onReorder(ids)` (`FavouritesViewModel.reorder`, which writes positions 0..n-1 and leaves out unknown ids), and the route reads the list again. A drag ended another way, or ending where it began, restores the order. A finger within 56 dp of the top or bottom edge scrolls the grid while held. A tile also has TalkBack actions Move earlier and Move later. The tiles in the test use `mainClock.advanceTimeBy` after `down` to pass the long press time. A line (`favourites_grid_hint`) says how to see a name and move a picture. The tiles use the 120 px pictures that the list uses, so they are slightly soft on a large phone.
- Owned and wanted look different on a discography row (`AlbumRow`): owned is the teal card (`primaryContainer`), wanted is the orange card (`secondaryContainer`) with a "Wanted" label, and an album that is neither has the plain card. Once an album is wanted, its `+ Want` pill goes: it comes off the list with the bin on the Wants page (`WantListViewModel.remove`, asked first with a confirmation, `want_remove_{albumId}`, `want_remove_confirm`, `want_remove_cancel`), or with the Wanted button on the album's details page. The album stays, as not wanted. An album that is owned never shows as wanted, because older saved rows can have both flags (`toggleOwned` clears the want, and the want list leaves out owned albums). `ThemeContrastTest` checks the text on both card colours.
- The discography header (`DiscographyHeader`) is the artist's name with a line under it: Artists (`artists_button`, goes to `Screen.Search`, the favourites page, whatever page you came from) and Save or Saved. The "Owned first" chip leads the format chip row (`FormatFilterBar` with `ownedFirst`), and is `rememberSaveable` in `DiscographyRoute`, so it is kept over a rotation. It is also kept for each artist across visits and app restarts: `OwnedFirstStore` (the `owned_first` preferences file, one true value per artist id, removed when switched off) is read by `MainActivity` into `startWithOwnedFirst` and written through `onOwnedFirstChange`. With it on, `DiscographyScreen` takes the owned albums out of their categories into an Owned section (`owned_section_header`) at the top, in the order of the categories, and a category left empty disappears. A chosen format narrows the Owned section too, and the format chips still count every album. Switching it on or off scrolls the list to the top, because the list keeps its place by item and the new section would otherwise sit above the screen. `DiscographyRouteTest` and `DiscographyScreenTest` run in a tall test window (`@Config(qualifiers = "w360dp-h2400dp")`), because the header and chips leave a LazyColumn no room in the default small one and its rows are never composed. A scroll test needs the small window, so it is in its own class (`DiscographyScreenScrollTest`).
- The user can choose their own photo for an artist, because some pictures from Wikimedia Commons are poor or missing. The artist's picture sits beside the name in the discography header, with a caption that says Add photo or Change photo (`change_photo`), and tapping it opens the system photo picker (`ActivityResultContracts.PickVisualMedia`, no permission needed). `ArtistPhotoViewModel` keeps the photo: `PhotoScaler` scales it to at most 600 px on its longest side as a JPEG (turned upright from the EXIF note, since decoding ignores that, and on white if it was transparent), `ArtistPhotoStore` writes it to `filesDir/artist_photos/{artistId}-{time}.jpg`, and the `artist_user_photos` table (database version 7) says which file belongs to which artist. Every photo gets a new file name, so a picture shown from the old file is not mistaken for the new, and the old file is deleted. The file name is made safe from the artist id. The Wikimedia picture is never touched. There is no way back to it from the app, on purpose: choosing a photo was a decision (the option "Use original photo" was removed), so a photo can only be replaced by another. `ArtistPictureSource` decides what is shown everywhere (header, favourites, search results): the user's photo first, and then the web is not asked at all. A photo over 30 MB is refused (`LimitedReader`), as is anything that is not a picture, with a short message. The "Artist photos: Wikimedia Commons" credit line still shows when only a user photo is on screen.

- Backup and restore (`backup` package, `BackupViewModel`) saves what the user chose and MusicBrainz cannot give back. A backup is a zip: `backup.json` (`BackupFile`: `app` "FindMeVinyl", `version` 1, favourite artists with `position`, the albums that are owned or wanted with `wantPosition`, which photo belongs to which artist, the favourite shops, and the `Settings`) and `photos/{fileName}`. Other albums are left out, because the discography loads them again; formats, statuses, covers and album details are fetched again too. Raise `BackupFile.VERSION` only when a field changes meaning. `restore` only adds: it reads and checks the whole zip first (a file that is not a zip, has no `backup.json`, is from another app, or has a newer version is `RestoreResult.Failed` and nothing changes), then merges in one Room transaction. An owned flag is never cleared, an owned album is no longer wanted, an artist already on the phone is kept as it is (name and position), an album already wanted keeps its place, a photo already chosen for the artist is kept, and the settings in the file replace the current ones. Restoring the same file again changes nothing. The photo name inside the file is never used as a path: the file gets a name made from the artist id (`safeFileName`) and the time, a photo must decode as a picture and be at most 5 MB, `backup.json` at most 20 MB, and the zip at most 5000 entries. The result counts only what was added.

- The Settings page has a Your data section (`SettingsRoute`, which `MainActivity` shows instead of `SettingsScreen` alone) with Back up (`backup_button`) and Restore (`restore_button`). The route owns the last message (`data_message`, `rememberSaveable`, so it survives a rotation) and a busy flag that disables both buttons while one runs. `MainActivity` does the file part with the system pickers, which need no permission: `ActivityResultContracts.CreateDocument("application/zip")` suggests `FindMeVinyl-backup-{date}.zip` and writes with mode `wt` so an older file is truncated, and `OpenDocument` is offered `*/*` because file apps do not agree on what a zip is called (a wrong file is refused by `BackupViewModel`). Both return null when the user backs out, and then nothing is said. The wording is in `BackupMessages` (counts only what was added). The pickers use a `CompletableDeferred` like the photo picker, so a rotation while the picker is open loses the result: the user taps again. Checked on the emulator: a backup was written, and a restore of a changed copy added one artist and one album and turned a setting on.
- Dependabot (`.github/dependabot.yml`) checks Gradle libraries and GitHub Actions monthly, in one grouped PR. It never offers Kotlin, KSP, AGP, the Compose BOM or the Gradle wrapper: a KSP patch update (2.2.10-2.0.2 to 2.2.21-2.0.5) broke the build with AGP 9, so those are moved by hand, with a build and an emulator check. For Room, Robolectric, OkHttp and Retrofit it offers patch updates only, because those versions were chosen to fix real problems. Treat its PRs like any other: the `test` check must pass, and ask before taking a version change.

## Running the app

- The emulator on this machine needs Graphics set to Software - GLES 2.0, or the screen stays black.
- Fake the GPS position with `adb emu geo fix <longitude> <latitude>` (longitude first). It resets when the emulator restarts.

## Known gaps

- Hiding bootlegs, promos and unknown status relies on the whole-artist check. An artist with more than 60 pages of releases is not checked that way, so only albums that have been looked up one by one (rows on screen) are hidden by status, and only from the next visit if the screen already showed them. MusicBrainz's release status is the only signal, so a bootleg with the wrong status stays shown.
- Search results are kept in memory only (`SearchResultCache.shared`). Rotation keeps them, but if Android kills the process the user gets the right screen and typed text back and has to search again. A search that is loading during a rotation is not resumed.
- The formats of an album are those of every release in its release group, so a later CD reissue of a record that was only ever on vinyl shows CD. Only the first 100 releases of a group are read. Format names that are not shown (DVD, SACD layers and so on) are ignored. New rows fill in at about one album a second, and the discography paging does not use the shared throttle.
- Artist pictures show on the search results and the favourites list (both use `ArtistImage` and `PhotoCredit`). A first search costs about two requests per visible artist (MusicBrainz and Wikidata), one a second, and nothing after that for 90 days. Coverage was only measured on well-known artists, so obscure artists may often have none. The picture is a photo cropped to a square, so some faces are cut off. The user cannot crop a chosen photo, and the screens centre-crop it into a square, so a tall photo loses its top and bottom. The photos are in the app's own folder, so they are lost with the app's data, unless the user has made a backup from Settings (Your data), which includes them.
- The detail page lists at most 30 pressings, and the list holds only the ones `PressingChooser.candidates` picks, so a non-vinyl pressing of a record that also came on vinyl is not listed. The rating is the average of MusicBrainz users' votes for the album, not for a pressing. A chosen pressing is not remembered. Opening an album not seen before costs three MusicBrainz requests. The album details do not open from the Wants list, on purpose: the Wants list is a list to share.
- Covers are cached in memory only. archive.org sends no cache headers, and every album costs a redirect request per run of the app. The cover is the release group's usual front cover, not the cover of a vinyl pressing.
- Try again after a failed page loads the discography again from page 1. A first page that fails with nothing saved shows only the error, with no Try again button. A list is built from every saved album, so an album MusicBrainz later removes from a discography still shows.
- The format filter is complete only after the check of the whole artist has finished (a line under the chips shows its progress). It starts by itself once a discography has settled, and an artist with more than 60 pages of releases (6000, more than anyone seen so far) is not checked this way and falls back to one lookup per row on screen, as before. Albums that none of the artist's releases belong to (for example a release credited to another artist) stay unchecked and keep the per-row lookups. A check that fails after three tries on a page says so with a Try again button, and keeps the pages it read for the next try. Progress is kept in memory only, so closing the app loses it. There is no "check all" button, no choosing more than one format, and the chosen format is not kept when you leave the artist.
- Opening hours use the phone's clock and time zone, so a shop in another time zone is judged by your local time. Public holidays are those of the region of the search area (a town, a place chosen from "Not the right place?", or your position), so a shop just over a border is judged by the wrong country's holidays. Holidays that depend on the shop's own town or religion are not known, and `SH` (school holidays) and other date rules make hours unreadable, so the raw text is shown. If Nager.Date cannot be reached and nothing is stored, the note that holidays may differ stays.
- The app has only been run on the emulator.
